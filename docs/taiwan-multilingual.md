# 대만 철도 다국어 표시

한국어가 기본 타이핑 언어다. 일본·홍콩과 같은 공통 노선 선택·지도·역명판 구조를 사용하며, 대만은 홍콩처럼 한국어 정답을 크게, 번체중문 원어명을 아래에 표시한다. 번체중문은 원래 저장된 `zh`/`names.zh`를 읽는 별도 표시 계층으로 제공한다. 영어는 추가 정보다. 한국·일본·홍콩의 표시 규칙은 바꾸지 않는다.

## 수정한 원인과 데이터 흐름

1. `taiwanKoreanPresentation()`이 입력용 `ja`/`kana`를 한국어로 바꾼 뒤 UI가 그 필드를 중국어로 읽어 같은 한국어를 반복했다. `js/taiwan-display.js`의 `getTaiwanDisplayNames()`, `taiwanNameText()`, `taiwanNameMarkup()`을 사용해 언어를 구분한다. 중국어를 `ja`에서 추측하지 않는다.
2. 공통 저장소가 운영사·노선·역의 `zh`를 제거했다. 대만 레코드에 한해 이를 보존한다. 한국어 편집 값은 `ko`에서 읽고 중국어는 별도로 유지한다.
3. 서비스 선택에는 한국어만 전달했다. 소스 빌더에서 `displayNames`와 출처·표시 종류를 추가하고 실제 선택 객체·게임 서비스까지 전달한다.
4. 단일 언어용 CSS의 고정 높이·절대 위치가 추가 언어를 자르거나 겹치게 했다. 대만 화면만 별도 행·줄바꿈·글꼴·대비·모바일 스크롤을 적용한다. 표시된 중국어는 툴팁이나 CSS 가상 요소에만 숨기지 않는다.
5. 과거 기록의 저장 이름만으로는 중국어가 없었다. 기존 route/service/station ID로 현재 카탈로그를 조회해 표시하며 기존 저장 레코드와 랭킹 키·요청 payload는 변경하지 않는다.

## 표시 범위

| 구성 요소 | 표시 |
|---|---|
| 국가·운영사 선택, 홈 추천 | 한국어·번체중문, 공식 로고 |
| 38개 물리 노선 카드·상세 | 한국어 우선, 번체중문 노선·운영사·양 끝 역, 기존 색상 |
| 운행·분기·방향·출발·도착 선택 | 한국어·번체중문, 기존 서비스 ID와 정차 순서 유지 |
| 역 검색·TAB 환승·자유주행 | 한국어·번체중문, ID로 연결하고 동명역 좌표를 합치지 않음 |
| 역명판·이전/다음 역·운행 정보 | 한국어(타이핑 정답) → 번체중문(현지 원어명) → 영어의 시각적 순서. 홍콩과 같은 한국어 우선 타이핑 계층을 사용한다 |
| 지도 라벨·정보·결과 지도 | 다국어 텍스트와 확대 가능한 정보, 실제 선형 유지 |
| 커스텀 편집·저장·목록 | 중국어 원본 보존 및 번체중문 검색, 사용자가 입력하는 중국어 노선명 필드 |
| 결과·최근 기록·개인 기록 | 기존 ID로 이름을 해석해 다국어 표시 |
| 노선별 개인·전체 랭킹·서비스 필터 | 기존 DB 키로 조회하고 표시만 다국어로 구성 |

543개 운영사 내 고유 역과 605개 노선별 역 레코드, 운행 패턴 250종·방향별 서비스 347개에 적용한다. 기존 선형·역 ID·정차역·서비스 ID를 그대로 비교 검사한다.

## 서비스 이름의 정직한 범위

TRA 및 아리산 등의 원본 열차 종류를 그대로 보존한다. 공항철도는 공식 [열차 안내](https://www.tymetro.com.tw/tymetro-new/tw/_pages/travel-guide/introduce.html)의 `直達車`·`普通車`를 사용한다. 원본에 별도 공식 서비스명이 없는 65개 방향은 원본 노선명과 실제 정차역 수를 설명 문구로 표시한다. 2개 순환 방향에는 지리적 방향을 덧붙인다. 이러한 설명을 공식 급행 브랜드 이름이라고 주장하지 않는다. 목적지·분기 구분은 해당 서비스의 실제 역 이름과 순서에서 가져온다.

기존 수록 데이터에서 누락된 번체중문 이름은 0건이다. 사용자가 만든 옛 커스텀 데이터에 `zh` 자체가 없으면 `ja`를 임의로 중국어라고 간주하거나 새 이름을 만들어 저장하지 않는다. 커스텀 중국어 이름은 편집기에서 명시적으로 입력할 수 있다.

## 검사와 재생성

```sh
node tools/build-taiwan.cjs
node tools/finalize-taiwan-report.cjs
node tools/build-app-bundle.js
node tools/audit-taiwan-multilingual.cjs
node --test tools/test-taiwan.cjs
node tools/test-taiwan-multilingual.cjs
```

브라우저 검사는 설치된 Playwright와 Chrome을 사용한다. 필요하면 `PLAYWRIGHT_MODULE`과 `CHROME_PATH`를 환경에 맞게 지정한다. 원본 역명·입력 답·별칭의 중국어 덮어쓰기, 중국어 누락, ID/선형/키 변경, 한국어 override 반영을 검사한다. 대만 입력에서는 중국어·가나·영문 전용 별칭을 허용하지 않는다.

실제 브라우저에서는 8개 운영사의 카드·서비스·역명판·지도와 대표 13개 운행을 검사한다. TAB 환승, 활성 자유주행, 커스텀 역 검색·저장, 결과·최근/개인 기록·랭킹, 390px 모바일·밝은/어두운 테마도 검사한다. 랭킹은 Supabase 형식의 **읽기 전용 모의 응답**으로 렌더링·쿼리 키를 확인한다. 운영 DB 쓰기·인증 계정 생성·실제 사용자 기록 변경은 하지 않는다. 물리 키보드 대신 한글 조합 이벤트를 사용한다.

결과·스크린샷은 `reports/taiwan/multilingual/`에 있다. 데이터/계약 감사는 `audit.json`, 대상 회귀 검사는 `regressions.log`, 실제 UI 증거는 `browser.json`을 참조한다. 전체 프로젝트의 과거 빌드 문제를 모두 해결했다고 주장하지 않으며 이번 검사는 다국어 UI와 관련 회귀에 한정한다.
