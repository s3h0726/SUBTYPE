# 대만 철도 구현 보고서

기준일: 2026-10-29. `feature/taiwan-railway`에서 구현했다. 운영사·노선·역·운행 종류·목적지와 타이핑 정답은 한국어이며 번체중문과 영어는 별도 메타데이터로 보존한다. 수동 한국어 음역은 검수 대기 상태이며 모든 표기가 공인 한국어 명칭이라는 뜻은 아니다.

| 타이완 고속철도 | 1 | 12 | 12 | 19 | 1 | 18 |

¹ 운영사 내 환승역 중복을 제거한 수. 운영사가 다른 환승역은 별개다. 공개 카드의 역 소속 관계는 584건, 분기 내부 트랙까지 포함한 좌표별 역 레코드는 605건이다. 동일 이름의 서로 다른 승강장 좌표를 합치지 않는다.

² 역 순서·정차 패턴의 방향 통합 집계. 일방향 운행 및 반대 방향의 상이한 정차 패턴 때문에 방향 수가 단순히 두 배가 되지는 않는다. 물리 노선 카드와 여객 운행은 구분한다. 루저우·단하이 분기는 내부 트랙으로 연결하고 중복 카드를 만들지 않는다.

TRA는 종관 북부·남부, 산선, 해선, 청쭈이, 핑둥, 이란, 북회, 타이둥, 남회, 쑤아오, 핑시, 선아오, 네이완, 류자, 지지, 사룬 17개를 수록한다. 지하철은 요청된 운영 구간과 분기, 싼잉선, 공항 보통·급행·일부 단축 운행을 수록한다. 고속철도 12역과 원본 시각표의 정차 조합을 사용한다. 아리산 4개 노선은 원본 산악 선형을 유지한다.

## 출처와 선형의 검증 범위

`data/tw/source/manifest.json`에 원본 URL·해시·취득 시각을 기록했다. TDX/OSM 사실 데이터의 중간 스냅샷은 [taiwan-rail-live](https://github.com/siriushsu/taiwan-rail-live)에서 취득했으며 15개 파일은 커밋 `288f95c3dbc88ac2c25805f95ddf6f365fbafc13`의 Git blob과 대조했다. 해당 프로젝트의 코드·음악은 복사하지 않았다. 공식 운영사 확인 URL은 빌더의 `officialSources`, 로고별 원본과 해시는 `data/tw/branding.json`에 있다. 추가 영어 명칭은 OSM의 이름과 근거리 좌표를 대조해 보완했다.

38개 물리 노선 모두 실제 선로 선형 스냅샷을 사용한다. 역 사이 직선 보간으로 선형을 만들지 않는다. 원본 꼭짓점을 유지하고 역을 선형에 순서대로 연결하며, 서로 맞지 않는 연결은 거부한다. 아리산 산악 곡선·루프·스위치백 선형과 가오슝 순환선의 마지막–첫 역 연결을 보존한다. 순환선은 양방향 한 바퀴 운행 후 출발역을 다시 입력시키지 않고 종료한다.

다만 전국 선형을 최신 공식 GIS/OSM 관계와 독립적으로 재검증한 노선은 **0개**다. 출처 추적·위상 검사와 최신 실측 정확성 인증을 혼동하지 않는다. 일부 TDX 스냅샷에 포함된 최신 공사·이설 반영 여부는 추가 확인이 필요하다.

## 상태와 남은 일

- `PLAYABLE`: 브라우저에서 실제 게임 엔진의 출발–종착 완료를 통과한 정확한 방향별 서비스 ID 13개. 공개 카드 12개를 대표한다.
- `IMPLEMENTED_UNVERIFIED`: 선택 가능한 나머지 334개 방향. 일괄 정차 순서·한국어·선형 연결 검사는 통과했으나 개별 전체 플레이 검증은 하지 않았다. 카드 자체도 모든 변형의 검증이 끝났다는 뜻으로 표시하지 않는다.
- `INCOMPLETE`: 산선/해선/청쭈이 분기 경로를 시각표 정차 정보만으로 확정하지 못한 TRA 139개 고유 방향 패턴(시각표 221행). `held-services.json`에 보관하고 선택 목록에서 제외했다.
- `RESEARCH`: 우라이, 타이핑산 봉봉열차와 제당 관광철도 5곳 등 7건. 실제 선형·현행 여객 운행 확보 전에는 일반 플레이 목록에 넣지 않는다.
- `EXCLUDED`: 미개통 연장·공항 미개통역·케이블카·비여객 시설·운휴 신마역 등 7건. [TRA 공식 공지](https://www.railway.gov.tw/tra-tip-web/tip/file/a21bfcce-ffab-4ec7-a688-60dbcc877d2a)에 따라 신마역은 여객 프롬프트에서 제외하고 통과 선형을 유지했다.

TRA 운행은 2026-10-29 시각표를 사용하되 정차역 사이 경로는 물리 네트워크에서 추론한다. 고속철도 정차 패턴은 2026년 7월 스냅샷이므로 기준일 최신 시각표와의 전수 대조는 남아 있다. 타이난 지하화 등 최근 선로 변경도 독립 GIS 확인이 필요하다. 모든 역이 각 선택 서비스의 정차역인 것은 아니다. 전 구간 전역정차나 임의 직결 운행을 자동 생성하지 않는다.

## 게임과 기존 기능

대만 국가 선택, 운영사 묶음, 철도 유형 탭, 한국어 방향·운행 선택, 공식 로고, 고속철도 카드, 밝은/어두운 테마와 모바일을 추가했다. 기존 한글 입력·점수·콤보 엔진을 사용한다. 편집표와 런타임 override를 연결하고 방향별 안정 ID를 기존 기록·순위 경로로 전달한다. 서버 데이터나 인증 스키마는 변경하지 않았다.

초기 작업 이후 원격 main이 갱신되어 최종 통합 시 `9dbe852a63f1d69115720ebddcfa5c29d01675dc`를 대만 브랜치에 병합했다. 최신 일본 역 ID·명칭·소부 쾌속선·선형 개선과 홍콩 통합을 보존한다. 대만 이외의 `data/` 파일은 이 기준 커밋과 차이가 없다. 홍콩 전용 브랜치는 수정하지 않았다. 최신 main의 한국 노선 초기화 정책(`koreaRoutesReset`)도 그대로 보존했으므로 현재 한국 카탈로그가 0개인 것은 이번 대만 추가로 발생한 삭제가 아니다. 운영 서버·Supabase 계정에 쓰기 검증은 하지 않았다.

## 재생성과 검사

원본은 `data/tw/source/`, 한국어 사전은 `data/tw/korean-names.txt`, 로고 등록은 `data/tw/branding.json`, 제외/조사는 `data/tw/research.json`, 변환 로직은 `tools/build-taiwan.cjs`다. 생성물만 수정하지 않는다.

```sh
node tools/build-taiwan.cjs
node tools/export-korean-names.js
node tools/build-app-bundle.js
node --test tools/test-taiwan.cjs
node tools/validate-taiwan-delivery.cjs
# PLAYWRIGHT_MODULE 및 CHROME_PATH를 설치 환경에 맞게 지정
node tools/test-taiwan-browser.cjs
node tools/finalize-taiwan-report.cjs
```

`finalize-taiwan-report.cjs`는 성공한 대표 브라우저 증거를 읽어 정확한 서비스 ID에만 QA 상태를 부여한다. 소스 재생성 후 필요하면 다시 실행한다. 이름 편집기는 `reports/korean-names/editor.html?branch=feature/taiwan-railway`로 열면 해당 브랜치를 대상으로 읽고 저장한다.

초기 기준에서는 통합 빌드와 대만·필수 회귀 57개가 성공했다. 최신 main을 가져온 최종 상태에서는 다음 결과를 얻었다.

- 앱 번들 생성, 대만 단위 검사 10개, 한글 입력 검사: 성공.
- 최신 구조용 통합 검사 14개: 성공. 대만 10개와 홍콩 선택기, 한국 초기화 정책, 소부 쾌속선, 일본 통합 역 ID 검사를 포함한다.
- 브라우저 대표 운행 13건, 다안 TAB 환승, 순환 양방향, 모바일 가로 넘침, 일본·홍콩 카탈로그와 한국 초기화 정책 보존: 성공.
- **전체 빌드: 실패.** `validate-data.js`가 기존 일본 역 마스터의 중복 ID 267건을 보고한다. 검사기와 해당 입력 데이터가 최신 main과 동일하고 대만 데이터는 이 검사에서 읽지 않음을 대조했다. 별도의 원본 데이터 정리가 필요하다.
- **기존 필수 회귀 묶음: 실패.** 초기화 이전 한국 경로를 요구하는 fixture, VM의 FEATURE_FLAGS 누락, 이전 일본 shared-station shard 위치 가정, 홍콩 환승 fixture가 현행 main과 맞지 않는다. 홍콩의 별도 과거 전체 검사에도 기존 스키마·소스 바이트 가정 관련 실패가 남아 있다. 이를 통과로 표시하지 않는다. 세부 사항은 `reports/taiwan/upstream-integration.json`, `essential-regressions.log`, `integration-regressions.log`에 있다.

한글 조합 이벤트를 합성해 검증했으므로 실제 키보드 IME·실계정 순위 저장까지 인증한 것은 아니다. 증거는 `reports/taiwan/` 및 `data/tw/generated/report.json`에 있다. `final-regressions.log`는 최신 main 통합 전 57개 검사 결과이며 최종 통합 상태의 전수 성공 증거로 사용하지 않는다.
