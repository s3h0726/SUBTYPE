# SUBTYPE 일본 전체 운영사 역명판 확대 — Phase 1

기준: 2026-11-08, `js/japan-lite-index.js`에 등록된 **161개 운영사 / 608개 노선 카드**.
이 단계는 전 운영사가 게임에서 최소 하나의 **CSS 역명판 계열**을 갖도록 하는 작업이며,
161개의 사진 기반 실물 역명판을 개별 복제했다는 의미가 아닙니다.

## 구현 범위

- 기존 전용 역명판은 보존: JR 6개 그룹, 신칸센, 도쿄메트로,
  도에이, 오사카메트로, 도큐, 오다큐, 에노덴, 치치부,
  케이오·케이큐·도부·세이부 등 대형 사철, 니시테츠.
- 나머지 일본 운영사에 대해 `station-sign-templates.js`가 반환하는
  `operator-private`, `operator-metro`, `operator-local`,
  `operator-tram`, `operator-monorail`, `operator-new-transit`,
  `local`, `tram`, `monorail` 계열을 새 공통형 역명판으로 적용.
- 기존 `data-operator-id`와 `--route-color`를 그대로 사용하므로
  한 운영사라도 노선별 색상 강조선과 현재역/이전역/다음역 표기가 연결됨.
- 중간 강조선은 `.station-sign-main::before`에 별도 레이어로 렌더링.
  기존처럼 `.station-sign-strip`을 뒤로 보내 하이라이트가 사라지지 않도록 설정.
- 각 계열별로 역명판 외곽, 바탕, 강조선 두께, 하단 바를 다르게 설계.
  시영 지하철, 해안·제3섹터, 모노레일·신교통, 관광철도, 노면전차에
  소규모 CSS 변형을 적용했으나 공식 실물 규격이라고 주장하지 않음.
- 태국·대만·홍콩·영국·한국 스타일은 선택자 `html[data-country="jp"]`로 격리.
- 한국어 입력과 자유주행 입력창 관련 JS, 역 순서, 노선 지오메트리,
  로그인·저장·랭킹 구조는 변경하지 않음.

## 검증 방법과 범위

```bash
npm run test:jp-nameplates
```

이 검사는 등록된 전체 노선의 `resolveStationSignTemplate` 결과가
기존 전용 역명판 또는 새 공통형 계열 중 하나에 속하는지 검사한다.
운영사 ID 연결, CSS 링크 순서, 일본 한정 적용, 전용 사진 역명판·
니시테츠 예외, 노선색 강조선, 한글 IME 노드 보존을 정적 확인한다.

**한계:** 정적 검사와 CSS 저장소 반영은 실제 웹 브라우저에서의
컴포지팅/색상 대비/가독성 보증이 아니다. 실제 일본 전 운영사,
모바일, 자유주행, 한국어 IME, Safari의 실화면 검증은 별도 필요하다.
`GitHub Pages` 배포 완료 여부와 실사이트 반영은 별도 확인한다.

## 다음 단계 — 사진 기반 개별 운영사 디자인

전 운영사별 진짜 역명판 모양을 완성하려면 노선/역/설치 세대별
사진 및 공식 운영사 자료를 확인한 뒤, 전용 CSS에서 철도별
배경 배치·실제 띠 위치·언어 우선순위·방향 화살표를 차례로 구현해야 한다.
우선 순위는 삿포로·센다이·나고야·교토·고베·후쿠오카 시영 지하철,
치바·다마·오사카·오키나와 모노레일, 히로시마·나가사키·가고시마 전차,
이즈급행·후지급행·하코네 등 이용 노선이 많은 그룹이다.

이미 완성된 CSS 전용 역명판의 **색상 가로선(하이라이트)**은 보존한다.
로고/역번호 숨김과 가로선 제거는 서로 다른 요구사항이다.
